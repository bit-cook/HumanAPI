02 / Authentication

认证

除 GET /api、GET /api/health、GET /api/ready 三个公开端点外，所有私有端点都需要 API Key。支持两种等价方式：

  • Authorization: Bearer <API_KEY>
  • x-api-key: <API_KEY>

服务端以常量时间比较校验 Key；缺失或不匹配返回 401，并带 WWW-Authenticate: Bearer 响应头。若服务端未配置 API_KEY 环境变量，私有端点返回 503。

请求示例

javascript · fetch
// 任选一种认证头，效果相同
const apiKey = process.env.HUMANAPI_API_KEY;

const response = await fetch("http://localhost:3000/api/humans", {
  headers: {
    authorization: `Bearer ${apiKey}`,
    // 或使用： "x-api-key": apiKey,
  },
});

if (response.status === 401) {
  throw new Error("API Key 缺失或无效");
}
安全提示：API Key 只应保存在服务端环境或 MCP 客户端环境中，不要写入浏览器端代码或提交进仓库。

03 / Conventions

约定

统一响应包络

所有端点返回 JSON。成功时为 { "success": true, "data": ..., "pagination"?: {...} }；失败时为 { "success": false, "error": "...", "details"?: [{ "field", "message" }] }。

成功 · 列表

json · 200
{
  "success": true,
  "data": [],
  "pagination": { "page": 1, "limit": 20, "total": 42, "totalPages": 3 }
}

失败 · 校验错误

json · 400
{
  "success": false,
  "error": "Validation failed",
  "details": [
    { "field": "rating", "message": "rating must be at most 5" }
  ]
}

ID 语义

字段含义
id / humanId（humans 相关）HumanProfile.id，专家档案主键
agentId / userId / reviewerId / senderId / reporterIdUser.id，用户主键
taskId / bookingId / disputeId / messageId各资源自主键

时间与金额

  • 时间字段使用 ISO 8601 字符串（含时区偏移），如 2026-11-05T02:00:00.000Z。
  • estimatedDuration 单位为分钟；maxDistance 与 distance 单位为米。
  • 金额字段 paymentAmount 与 hourlyRate 跟随 currency 字段（默认 CNY）。

专家 humans

专家档案（HumanProfile）是匹配与预约的核心资源。默认只返回 verified: true 的档案。

ratingMinnumber0最低评分（0–5）

pagenumber1页码

GET /api/bookings 需要 API Key

请求体

humanIdstring是HumanProfile.id（注意不是 User.id）
scheduledTimestring是计划执行时间（ISO 8601）
estimatedDurationnumber是预计时长（分钟）

POST /api/bookings/:id/:action 需要 API Key

预约状态迁移。action 决定目标状态与连带效果；非法迁移返回 409，预约不存在返回 404。

状态迁移表

action迁移连带效果可选 body
confirmPENDING → CONFIRMED任务置 ASSIGNED—
startCONFIRMED → IN_PROGRESS任务置 IN_PROGRESS，记录 startedAt—
completeIN_PROGRESS → COMPLETED任务置 COMPLETED，记录 completedAt，专家 totalTasks +1completionProof、actualDuration
cancelPENDING / CONFIRMED / IN_PROGRESS → CANCELLED任务置 CANCELLED—
disputePENDING / CONFIRMED / IN_PROGRESS → DISPUTED任务状态不变（等价于快捷创建争议）reason、description
resolveDISPUTED → COMPLETED任务置 COMPLETED，专家 totalTasks +1completionProof、actualDuration

请求示例

javascript · fetch
const bookingId = "bkg_5t8wa31q";

// complete 可附带完成凭据
const response = await fetch(`http://localhost:3000/api/bookings/${bookingId}/complete`, {
  method: "POST",
  headers: {

11 / Errors

状态码与错误

所有错误响应都是 JSON，并遵循统一的失败包络。未知路由同样返回 JSON 404，而不是 HTML 页面。

状态码含义常见场景
200成功查询、更新与状态迁移成功
201已创建POST humans / tasks / bookings / reviews / messages / disputes
400参数错误校验失败，details 含字段级错误
401未认证缺少或无效 API Key，带 WWW-Authenticate: Bearer
404不存在资源不存在；未知路由返回 JSON 404
409冲突非法状态迁移、任务已被抢占、重复评价或重复争议
429触发限流超过每 Key 限额，带 Retry-After
500服务端错误未处理的内部异常
503不可用服务端未配置 API_KEY，或 /api/ready 探测数据库失败

错误响应示例 · 401

json
{
  "success": false,
  "error": "Authentication required"
}

12 / Limits

限流与安全响应头

限流

每个 API Key 一个滑动窗口计数器，默认 120 次 / 60 秒。超限返回 429，并带 Retry-After 与 X-RateLimit-Limit / X-RateLimit-Remaining / X-RateLimit-Reset 响应头。限额可通过环境变量调整：

环境变量默认说明
RATE_LIMIT_MAX120窗口内最大请求数
RATE_LIMIT_WINDOW_MS60000窗口长度（毫秒）

限流响应示例 · 429

json
{
  "success": false,
  "error": "Rate limit exceeded",
  "details": [
    { "field": "rateLimit", "message": "At most 120 requests per window" }
  ]
}
当前实现为单进程内存计数，适合单体参考部署；多副本水平扩展前应替换为共享存储（如 Redis）。

安全响应头

API 响应统一附加以下安全响应头：

响应头作用
X-Content-Type-Options阻止浏览器嗅探内容类型
X-Frame-Options禁止被嵌入框架，降低点击劫持风险
Referrer-Policy限制跨站请求携带的 Referer 信息
Permissions-Policy收紧浏览器特性权限
Strict-Transport-Security强制后续访问使用 HTTPS
X-DNS-Prefetch-Control关闭 DNS 预读取，减少信息外泄
